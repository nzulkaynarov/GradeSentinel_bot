# Модернизация под актуальный Telegram API — ресерч и план

> 05.09.2026. Причина: бот и Mini App построены на возможностях 2024 года, Telegram с тех пор
> выпустил 15 версий Bot API. Документ — что именно мы пропустили, что из этого стоит взять
> и в каком порядке. Код по итогам ресерча пока не менялся, кроме апгрейда библиотеки.

## Размер отставания

| | Было у нас | Актуально на 05.09.2026 | Разрыв |
|---|---|---|---|
| Bot API | 7.4 (28 мая 2024) | **10.3** (24 авг 2026) | 15 версий |
| pyTelegramBotAPI | 4.21.0 | **4.36.1** (покрывает Bot API 10.2) | 15 релизов |
| Mini App SDK | фактически уровень 6.x | 10.1 | ~8 версий |

Библиотека покрывает Bot API 10.2, поэтому фичи 10.3 (rich messages, `DisabledButton`)
пока доступны только ручными вызовами. Это не блокер — в списке ниже их нет.

## Что мы используем сегодня

**Бот** — 20 методов: `send_message`, `send_document`, `send_invoice`, `edit_message_text`,
`copy_message`, `forward_message`, `delete_message`, `answer_callback_query`,
`answer_pre_checkout_query`, `refund_star_payment`, `set_chat_menu_button`, `set_my_commands`,
`send_chat_action`, `reply_to`, `get_me`, `polling` + 4 декоратора-хендлера.
Типы: инлайн- и reply-клавиатуры, `WebAppInfo`, `LabeledPrice`, `MenuButtonWebApp`.

**Mini App** — 7 методов SDK: `ready`, `expand`, `close`, `HapticFeedback`, `showAlert`,
`showPopup`, `openTelegramLink`. Это уровень Bot API 6.x.

## Три находки аудита

1. **Telegram Stars уже написаны, но выключены.** `handlers/subscription/_common.py` собирает
   провайдер `stars` (currency `XTR`, без `provider_token`), `payments.py` умеет XTR-ветку и
   возврат через `refund_star_payment`. На проде `STARS_ENABLED` пустой → способ оплаты, не
   требующий ни мерчанта, ни Click/Payme, просто не предлагается пользователю.
2. **Нативных подписок нет.** `subscription_period` (Bot API 8.0) не используется. Важная
   деталь реализации: в pyTelegramBotAPI 4.36.1 этот параметр есть **только у
   `create_invoice_link`**, у `send_invoice` его нет. Значит рекуррентная подписка делается
   через invoice-ссылку, а не через привычный нам `send_invoice` — это переписывание флоу,
   а не добавление одного аргумента.
3. **Версию клиента нигде не проверяем.** `isVersionAtLeast` не встречается в `app.js`.
   Любой новый вызов SDK обязан быть за проверкой версии, иначе на старом клиенте родителя
   он молча не сработает (или уронит инициализацию дашборда).

| Star-подписки (`subscription_period`) | 8.0 | Автопродление без ручного `/grant_sub`; управление подпиской на стороне Telegram. Бьёт в renewal — главную бизнес-метрику |
| Включить `STARS_ENABLED` | 7.4 | Рабочий платёжный канал, код готов. Реалистично — для диаспоры: у родителей в Узбекистане Stars менее привычны, чем Click/Payme |

### Сознательно не берём

Gifts, giveaways, stories, business-аккаунты, paid media, affiliate, communities, live photos,
managed bots — не про школьный дневник. Paid broadcast (7.11) — платная рассылка, нам не нужна.

## Порядок работ

**Этап 0 — апгрейд библиотеки. Сделано, ждёт мержа.** Ветка `chore/bump-pytelegrambotapi`:
4.21.0 → 4.36.1, 640 тестов зелёные против нового образа. Проверено, что все 20 используемых
методов на месте, `disable_web_page_preview` (устарел в 7.0) всё ещё принимается, платёжные
сигнатуры совместимы. Лок вырос на 8 пакетов — с 4.36.1 `aiohttp` стал обязательной
зависимостью апстрима; на RAM бота не влияет, `async_telebot` мы не импортируем.

Дальше — отдельными PR, каждый от `main`, по одному за раз:

**Этап 1 — сообщения.** Самый низкий риск, заметный эффект «бот ожил»: нативный стриминг,
сворачиваемые AI-отчёты, реакции, `date_time`. Ничего не ломает при откате.

**Этап 2 — Mini App.** Fullscreen + safe area, `MainButton`/`SecondaryButton`, CloudStorage
вместо localStorage, home screen, `downloadFile`. Обязательное условие: каждый вызов за
`isVersionAtLeast`, плюс фоллбэк на текущее поведение.

**Этап 3 — деньги.** Star-подписки через `create_invoice_link` + `STARS_ENABLED`.
Идёт последним не потому что неважно, а потому что трогает реальные платежи: нужен прогон
на себе (покупка, автопродление, возврат) до того, как это увидит родитель.

## Риски

- **Проверка версии клиента.** Главный источник тихих поломок в Mini App. Без `isVersionAtLeast`
  новый вызов на старом Telegram ломает инициализацию дашборда целиком.
- **Мерж = деплой.** Каждый этап проверять на проде отдельно, не копить несколько PR в один
  деплой (грабли стековых PR из сентябрьской сессии).
- **Не геймифицировать оценки.** Эффекты и реакции — только на усилие и редкий позитив.
  Ресерч по летнему режиму: «очки за оценки» повышают тревожность.
- **Тесты мокают Bot API,** поэтому зелёный сьют не доказывает совместимость вызовов.
  Для каждого этапа — ручная проверка живым ботом.
