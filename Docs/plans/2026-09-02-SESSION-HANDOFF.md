### Что сделать на проде (владелец, DB-VPS)

```sql
-- останавливает рассылку немедленно
UPDATE students SET academic_year = 2025 WHERE id = 1;
-- убирает мусор из истории (искажает дашборд, AI-анализ и будущие backfill'ы)
DELETE FROM grade_history WHERE id IN (8087, 8088, 8089);
```
Проверка: `make prod-sql SQL="select id, display_name, academic_year from students"` → 2025 у обоих;
в ближайшем цикле в логах появится `[STALE_SHEET]` по ученику 1.

Альтернатива без ручного SQL — смержить PR с самовосстановлением (ниже): код сам понизит год,
сверив содержимое листа.

## Грабли, на которые наступали в этой сессии

- **Тесты нельзя гонять параллельно** (несколько агентов на одной тестовой БД) — `temp_db` делает
  TRUNCATE и роняет чужой прогон психопг-ошибками. Один прогон за раз.
- **Сезонные тесты**: 7 тестов с датами вида «сегодня − N» и датами мая без года **падали на main с
  1 сентября**. Правило: фиксированные даты либо явный `academic_year=`.
- **Прод-БД только на чтение**: write-команды через ssh блокируются политикой; готовый SQL отдавать
  владельцу.
